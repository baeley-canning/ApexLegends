2. MATCH INFECTION RATE (MIR) SYSTEM
================================================================================

Definition:
- Tracks both CONFIRMED AND SUSPECTED cheaters
- Measures confidence that at least one cheater impacted any given match
- EA prefers MIR over raw ban counts (banning doesn't undo ruined matches)

Key Metrics:
- MIR increased from 2.28% to 3.09% in January 2026
- Post-launch MIR: ~2% (98% of matches fair and clean)
- "Stealth cheats" (avoiding "high impact") cause MIR to rise

New Ban Acceleration (Deployed Jan 26, 2026):
- Impacts MIR calculations
- Includes suspected cheaters in ban waves
- Refines detection signals continuously

================================================================================
3. THREE-STEP ENFORCEMENT PROCESS
================================================================================

1. PREVENT cheating when possible (block before function)
2. DETECT when it gets through
3. ACT with evidence-based enforcement

Key Insight: Prevention ≠ Bans
- 265,550 prevented attempts in Apex week one
- Only 12,969 bans (many stopped before ban threshold)

5. EXTERNAL CHEATS CAN BE UNDETECTED
================================================================================

Key EA Quotes (Sep 2026):
- "We operate at kernel level because detecting external cheats requires it, 
   not because we want deeper access."
- "Javelin only runs when a game with Javelin protection included is running."
- "Cheat providers often advertise 'undetectable' status, a claim that's always temporary."

External Cheat Advantages:
- Don't interact with game process directly
- Can operate at kernel level (separate from game)
- External overlays don't inject into game memory
- Javelin auto-uninstalls when no EA games present

6. KERNEL-LEVEL ARCHITECTURE
================================================================================

Technical Details:
- Operates at Ring 0 (kernel mode)

Driver Components:
- User-mode agent + Kernel driver

10. CURRENT LIMITATIONS & BYPASS METHODS
================================================================================

Known Bypass Methods:
- Direct Memory Access (DMA) cheat hardware
- Physical PCIe devices that read memory externally
- Griffin VM integration (obfuscation)
- Behavioral spoofing (matching human baselines)

Limitations:
- DMA cheats harder to detect (external hardware)
- "Stealth cheats" not counted until they're confirmed
- Kernel-level access privacy concerns

12. RECOMMENDED EVASION STRATEGIES FOR CUSTOM CHEAT
================================================================================

Priority Focus Areas:

1. Griffin VM Integration (Medium Detection Risk)
   - Use Griffin's existing patterns (less suspicious than custom ones)
   - Integrate with Javelin's VM obfuscation pipeline
   - Leverage Griffin's MBA patterns for signature hiding

2. Behavioral Biometrics (High Impact, Low Risk)
   - Match human baselines: reaction times N(250ms, σ=75ms)
   - Micro-jitter: N(0, σ=1.5°) at 60Hz
   - Rank-matched performance profiles

3. Kernel-Level Protection (C++ Kernel Driver)
   - Minimalist approach for lowest ban likelihood
   - KDMapper injection (well-established, low suspicion)
   - Telemetry collection in kernel mode

4. Telemetry Obfuscation (EASPEAR-Style)
   - Batching to match human patterns
   - Behavioral pattern alignment
   - Cross-game signature sharing
