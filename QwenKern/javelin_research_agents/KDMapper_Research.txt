1. OVERVIEW: KDMAPPER ARCHITECTURE
================================================================================

KDMapper is a user-mode application that exploits the vulnerable Intel driver
(iqvw64e.sys) to manually map non-signed kernel drivers into memory.

Key Features:
- Manual mapping bypasses Windows' normal driver load
- No installation required - maps directly into kernel memory
- Works with unsigned drivers without DSE (Driver Signature Enforcement)
- Designed for quick deployment without complex configuration

================================================================================
2. KDMAPPER TECHNICAL MECHANICS
================================================================================

Driver Mapping Process:
1. Load vulnerable Intel driver (iqvw64e.sys) as entry point
2. Allocate kernel memory for target driver
3. Copy PE image into allocated memory
4. Resolve imports and relocations
5. Call DriverEntry point

This makes KDMapper a "nuclear bomb" in the Windows internals scene.

================================================================================
3. INTEL DRIVER (IQVW64E.SYS) DETAILS
================================================================================

 iqvw64e.sys is an old network diagnosis driver from Intel:
- Legacy driver with well-known vulnerability
- Exposes kernel memory read/write to user mode
- Used by KDMapper as the "mapper" entry point
- Well-established pattern - less suspicious to Javelin

5. DETECTION VECTORS FOR MANUAL MAPPING
================================================================================

Detection depends on:
- Whether executing in non-signed memory or not
- Import resolution method (doesn't matter to Javelin unless dumped)
- Virtualization state of the driver

Best Practice: Manual map into signed memory and avoid constant execution
(e.g., basic driver with no communications).
