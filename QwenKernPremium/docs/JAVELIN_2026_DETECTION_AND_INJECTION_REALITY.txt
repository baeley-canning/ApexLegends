2. HARD CONSTRAINTS OBSERVED BY INJECTOR AUTHORS POST-JAVELIN
--------------------------------------------------------------------------------
[RE] 2026-10-09 UC "injector issue":
  - ZwAllocateVirtualMemory with PAGE_EXECUTE now FAILS inside Apex;
    ZwProtectVirtualMemory effectively unusable there.
  - Author's workaround: clear the NX bit in the PTE, set page RX. Side effect:
    VAD mismatch, expected to be catchable.
  - Senior responder's advice: map via MDL (VAD-less). Caveats he flagged:
    MDL regions unmap automatically on process exit; CRT init FAILS in VAD-less
    memory because the CRT calls VirtualProtect internally -> must IAT-redirect
    VirtualProtect to a stub returning success during DllMain, then restore.
  - Suspected root cause: AGC / dynamic-code policy.
[RE] 2026-10-15 same thread: reflective injection that worked under EAC now
  freezes under Javelin. An EV+attestation-signed-loader author states the
  answer is understanding Apex's Javelin implementation first and signing the
  LOADER AND THE DLL. Another notes Javelin installs a manipulated CR3 into the
  game process.
[RE] 2026-10-18 resolution posted: two root causes were (a) ACG and (b) getting
  the module "recognised as trusted"; once fixed, reflective injection AND a
  DX12 Present hook ran without stutter.

*** ACTIONABLE: the classic VirtualAllocEx(PAGE_EXECUTE_READWRITE) +
    CreateRemoteThread(LoadLibrary) chain is now the WEAKEST option for Apex.
    Order of preference becomes: signed-driver-assisted load / MDL or VAD-less
    reflective map / APC+MDL / plain CRT. Assume ACG unless proven otherwise. ***

3. KERNEL SIDE: NOW-UNAVOIDABLE TOPICS
--------------------------------------------------------------------------------
[RE] UC "EAAC unbacked kernel memory" (2026-10-10):
  - Symptom: "with my driver loaded the game closes after a few minutes; with
    the driver unloaded it runs fine" => detection occurs while the driver is
    present but IDLE (no reads, no writes). Presence of unbacked kernel memory
    is enough.
  - Community answers: (a) use a "ghost stomp" style mapping so the image looks
    backed; (b) stop treating kdmapper alone as sufficient in 2026; (c) get the
    driver SIGNED (EV + attestation) and load it as a real service; (d) note
    that MmCopyMemory itself is suspected to be a flag.
[RE] tulach, "detecting manually mapped drivers": scanners enumerate physical
  memory (MmGetPhysicalMemoryRanges + chunked MmCopyMemory) and hunt for
  compiler-generated tell-tales OUTSIDE any legitimate module region. Their
  best detector: absolute indirect jump import thunks (FF 25 xx xx xx xx) whose
  resolved target IS in ntoskrnl but whose thunk address is NOT inside a real
  module. Zeroing DOS/NT headers is not enough to hide.
[RE] hlunaaa, "bypassing CR3 abuse": EAC and Vanguard already conceal
  KPROCESS.DirectoryTableBase by relocating the address space via page-table
  surgery at startup; Javelin is reported to do the same for Apex. Counter:
  brute-force PML4 self-reference across physical ranges, validate a candidate
  CR3 by translating a known user VA (e.g. EPROCESS.SectionBaseAddress) and
  checking for 'ZM' at the MZ offset.
[RE] Consequence: a driver that caches DirectoryTableBase once at attach can
  read the wrong physical pages under Javelin. The robust read primitive is
  physical access + PML4 self-ref walk, optionally memoised per launch.

4. IMPACT OF THE ABOVE ON OUR TWO PATHS
--------------------------------------------------------------------------------
Path A - user-mode injector into r5apex_dx12.exe (today's default):
  - Must survive ACG: RW alloc -> write -> attempt VirtualProtect(RX) -> on
    failure fall back to PTE/NX manipulation -> then MDL/VAD-less mapping.
  - Must satisfy the "trusted module" expectation [RE]: sign the DLL, keep the
    IAT minimal (already true: only d3d11/kernel32/user32 after the d3d9 +
    d3dcompiler removal), and choose deliberately between "be a normal module"
    (visible, clean) and "be unbacked" (invisible, needs ghost-stomp hygiene).
  - Loader must detect ACG state in the target and select the strategy, instead
    of hard-failing like the UC author did.
Path B - kernel driver (apexdrv) as read/comm layer:
  - kdmapper-only presence is now a medium risk. 2026 direction: EV cert ->
    attestation-signed driver (no HLK needed) -> normal service load, so it
    passes HVCI/Secure Boot/VBS cleanly and is off the "unbacked" hook.
  - Keep comm off IOCTL-dispatch hooks: shared memory section is the community
    norm and the easiest to keep clean.
  - Implement BOTH read primitives: (i) physical + PML4-walk (CR3-abuse-proof),
    (ii) attach-process/section path as a fast case when CR3 is not moved.
  - Also budget for the Javelin ERROR #119 denylist: a *vulnerable driver* used
    as a loader (e.g. iqvw64e.sys style) can be denylisted by name — the loader
    must be able to switch exploit drivers.
