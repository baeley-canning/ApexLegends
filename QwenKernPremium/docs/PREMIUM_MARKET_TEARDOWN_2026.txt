0. METHOD / CAVEAT
--------------------------------------------------------------------------------
Vendor pages are marketing. What is trustworthy is the SHAPE of the feature
taxonomy and the operational promises they make (update cadence, status pages,
support). A vendor claim of "undetected" is positioning, not proof.

2. THE PREMIUM BAR — WHAT WE MUST SHIP TO BE COMPETITIVE
--------------------------------------------------------------------------------
Must-have (table stakes — every product above has it):
  [ ] Humanised aim smoothing, per-weapon(-category) profiles, prediction
  [ ] Skeleton + health/shield + name + distance, team/downed/visible filters
  [ ] Glow (player/item/deathbox) with rarity + distance limits
  [ ] Config presets, toggle menu, hotkeys, custom colours
  [ ] Streamproof + screenshot-safe rendering, disableable watermark
  [ ] Spectator awareness (spectator count, glow-when-spectated, aim disable)
Should-have (separates premium from public/free):
  [ ] Movement module (BHOP, tap strafe, super glide, wall jump, auto grapple)
  [ ] World/loot ESP by category + rarity
  [ ] 2D radar in-overlay, ideally a web/2nd-display radar
  [ ] Triggerbot with detection threshold + magnetic mode
  [ ] Cosmetic layer (weapon/player skin changer, glow weapon)
  [ ] Robust offset updater: patch-day fixes without client re-download
  [ ] Public status page + fast comms
Operational (what actually retains users):
  [ ] Post-patch update latency target < 2h (market punishes 24h vendors)
  [ ] Loader UX: pre-flight checks, one-click inject, readable error codes
  [ ] Support channel + response SLA
  [ ] HWID spoofer story if the user has ever been banned

--------------------------------------------------------------------------------
3. WHAT THE MARKET TREATS AS "DETECTION SAFETY"
--------------------------------------------------------------------------------
Recurring themes in vendor copy and community research:
  - Load/late-load ordering vs the anti-cheat driver (see JAVELIN KB file)
  - Closed user base / private builds (fewer samples for analysts)
  - Rolling code identity: TATEWARE claims weekly polymorphism; a static binary
    eventually gets fingerprinted
  - Behavioural humanisation: Respawn's own layer flags otherwise "perfect"
    recoil (R-301 pattern), impossible reaction time, super-human hit ratios —
    so aim quality IS an anti-detection control
  - Streamproof / capture-invisible overlays sold as user-facing safety
  - HWID spoofing, because Apex hardware bans are aggressive and visible
  => Our evasion story must not be binary-only. Humanisation and profile
     discipline are engineering, not cosmetics.

--------------------------------------------------------------------------------
4. DIFFERENTIATION IDEAS WORTH BEATING THE MARKET ON
--------------------------------------------------------------------------------
1. TELL THE TRUTH ABOUT ARCHITECTURE: publish which layer is evadable when and
   what is proven by testing. No vendor above explains their own evasion.
2. SELF-DIAGNOSING OFFSETS: turn the existing OffsetValidator into a
   signature/AOB-driven resolver so a patch degrades gracefully and the loader
   can report "offsets stale" BEFORE the user queues a match.
3. SAFETY PRESETS: "Closet / Balanced / Rage" bundles (smoothing + reaction
   delay + spectator handling + trigger delay) plus a one-key emergency detach.
4. REAL SPECTATOR-AWARE MODE driven off observer-list reads (Kernaim has the
   bullet point; nobody convincingly implements it).
5. WEB RADAR (Eclipse model) reusing the existing memory-read path: cheap to
   build, large perceived value, usable on a second screen/phone.
6. LOADER PRE-FLIGHT: game build check, IAT hygiene check, driver load state,
   ACG/HVCI/Secure Boot detection, denylisted-driver (#119) presence, then a
   single recommended inject strategy.
7. UPDATER INTEGRITY: signed manifest + hash-pinned offsets so a user cannot
   run a stale or half-updated build.
