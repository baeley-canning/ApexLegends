5. WHAT THIS MEANS (actionable)
--------------------------------------------------------------------------------
1. A1/A2/A3 are NOT "wrong methods" right now: they cannot even allocate in the
   target. Re-ordering the ladder will not help; the ACCESS has to be fixed.
2. B3 (kernel driver) becomes the PRIMARY rung: it needs no user-mode handle, no
   remote allocation and no readable module list, and it can map/read from kernel
   context where CR3 abuse does not apply. Budget: build+sign apexdrv.sys (see
   JAVELIN_2026 file, Path B; ERROR #119 denylist risk applies).
3. An EXTERNAL reader is blocked too (RPM fails), so "external overlay" is not a
   workaround on its own until reads work.
4. A7 (manual map) / A8 (VAD-less) stay gated on X2/X4 succeeding inside the
   target; the harness will say the moment that changes.
5. Reference-integrity output against a live game is currently "unknown" for the
   render modules because the module list itself is unreadable. Any claim of
   "d3d11 absent/present in Apex" made before this date is unverified.

Next actions (in order):
  a) re-run these measurements with the game at the MAIN MENU vs IN MATCH (ACG
     arming is stage dependent) and after a clean reboot (no stale EAC state);
  b) try NtOpenProcess / duplicated EAC handles and smaller masks (e.g.
     CREATE_THREAD|VM_OPERATION only) to see whether the denial is mask related;
  c) build apexdrv.sys (WDK is missing on this box) so B3 can be measured - the
     rung is already wired and only SKIPs on a missing file;
  d) check whether the launcher's session/integrity level relative to the target
     matters (run launcher as SYSTEM / from a service).
