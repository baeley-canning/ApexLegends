LESSON (durable, this is the second host crash from my own probe shape, cf. p331):
  1. p4 can bugcheck, so it is a VM-bench probe by R1 -- not a host-first probe. It went to the
     host because everything before it was read-only; "read-only" clearly does not imply "cannot
     bugcheck" for this driver.
  2. log-before-work must survive a bugcheck: append the *next* address to a separate `.cur`
     file with os.fsync() before each risky read, small chunks (4 KB), wall-clock budget and a
     watchdog. A flushed stdout into a redirect is not enough.
  3. Never let p4's scan be the first thing a fresh boot sees; the class test is one `read_phys`
     away from the fault, so keep the chunk small and the probe re-runnable.
